<code>.sluglist/</code> folder — browser JS can&#39;t touch disk, so this tiny process does.</li>

<h2>Why agents resolve these reports well</h2>
<p>Every issue is a markdown file written for a file-reading agent, not a human dashboard:</p>
<ul>
<li><strong>A smart CSS selector</strong> (<code>data-testid</code> → <code>id</code> → <code>aria</code> → landmark path — never Tailwind
utility or hashed classes), plus <code>dom_path</code> and <code>element_text</code>, localize the element.</li>
<li><strong>A React component hint</strong> — sluglist reads the nearest named component from the element&#39;s fiber
and records <code>component: AnimalForm</code>. No React dependency required; <code>null</code> when unavailable.</li>
<li><strong><code>## Errors</code></strong> carries recent console errors, uncaught exceptions and failed requests
(<code>PATCH /api/animals/128 → 500</code>) with relative timestamps — often the root cause is already in
the report.</li>
<li><strong><code>## Actions</code> + record-mode frames</strong> give steps-to-reproduce as numbered screenshots,
cross-referenced line by line.</li>
</ul>
<p>The agent doesn&#39;t guess what the user meant; it reads what the page knew.</p>
<h2>The other direction: agent-generated checklists</h2>
<p>The second bundled skill, <code>sluglist-checklist</code>, turns a branch diff into a client-facing
acceptance checklist. The client walks it on staging, checks items off or flags problems, and every
verdict lands in <code>session.yaml</code> — which the agent can read back to see what failed.
See <a href="/docs/checklist/">Checklist mode</a>.</p>
<h2>Not just Claude Code</h2>
<p>The artifacts are <a href="/docs/artifacts/">a stable, documented format</a> — plain markdown, YAML and PNG in
a folder. Any agent or script that can read files can consume them; the Claude Code skills are a
convenience, not a dependency.</p>
