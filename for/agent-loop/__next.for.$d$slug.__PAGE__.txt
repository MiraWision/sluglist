<h2>Set the project up</h2>
<pre class="shiki shiki-themes light-plus dark-plus" style="--shiki-light:#000000;--shiki-dark:#D4D4D4;--shiki-light-bg:#FFFFFF;--shiki-dark-bg:#1E1E1E" tabindex="0"><code><span class="line"><span style="--shiki-light:#795E26;--shiki-dark:#DCDCAA">npx</span><span style="--shiki-light:#A31515;--shiki-dark:#CE9178"> sluglist</span><span style="--shiki-light:#A31515;--shiki-dark:#CE9178"> init</span><span style="--shiki-light:#0000FF;--shiki-dark:#569CD6"> --agents-md</span></span></code></pre><p>That installs the four bundled skills into <code>.claude/skills/</code>, creates <code>.sluglist/checklists/</code>,
writes the <code>.gitignore</code> rules, and drops a <code>.sluglist/PROJECT.md</code> to fill in. Fill it in — it is
where the loop learns your base branch, how to start the app, how to sign in (referenced, never
stored), the actions it must never complete, and how far it may go on its own:</p>
<pre class="shiki shiki-themes light-plus dark-plus" style="--shiki-light:#000000;--shiki-dark:#D4D4D4;--shiki-light-bg:#FFFFFF;--shiki-dark-bg:#1E1E1E" tabindex="0"><code><span class="line"><span>max rounds: 3</span></span>
<span class="line"><span>fix without asking: no</span></span>
<span class="line"><span>commits: leave the changes uncommitted, one summary at the end</span></span></code></pre><h2>Ask for the whole thing</h2>
<div class="callout callout-quote"><div class="callout-body"><p>QA this branch and fix everything until it passes.</p>
</div></div><p>The <code>sluglist-loop</code> skill takes it from there:</p>
<ol>
<li><strong>Checklist</strong> — the branch diff becomes a client-voice list at <code>.sluglist/checklists/</code>.</li>
<li><strong>QA run</strong> — a browser walks every item and writes verdicts and issues through the headless
writer, <code>sluglist/node</code>.</li>
<li><strong>Report</strong> — <code>npx sluglist report</code> renders the round as one HTML file.</li>
<li><strong>Status</strong> — <code>npx sluglist status --json</code> says what is still failing and whether it is worth
another round.</li>
<li><strong>Fix</strong> — the failing issues are patched; each outcome is recorded in <code>fixes.yaml</code>.</li>
<li><strong>Re-test</strong> — a checklist of only the fixed items, ids preserved and provenance attached, then
back to step 4.</li>
</ol>
<p><strong>See the output for yourself:</strong> <a href="/example-report.html">a live example report</a> — one
self-contained HTML file from a real QA round on a demo app: evidence-backed passes with the
observed facts, a fail linked to its issue, an item honestly reported as <em>not tested</em>, and the fix
pass answering in <code>fixes.yaml</code>.</p>

<h2>The guarantees that make it usable</h2>
<ul>
<li><strong>No fail without a screenshot; no pass without performing the check.</strong> An unreachable item is
<em>not tested</em>, with the reason.</li>
<li><strong>A screenshot proves the screen looked right, never that the action worked.</strong> For downloads,
submissions and background jobs the verdict carries the observed fact — the file name and size,
the toast text, the row count.</li>
<li><strong>The loop may not manufacture green.</strong> It cannot edit, narrow or delete a check so it stops
failing, and it cannot write <code>wontfix</code> to end a round; those are proposals surfaced to you.</li>
<li><strong>Hard limits are enforced.</strong> Live payments, real emails, external submissions: the run stops at
the last safe step and records <em>not tested</em> with the reason.</li>
</ul>
