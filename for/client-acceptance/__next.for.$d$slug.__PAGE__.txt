<p>A second circle appears above the feedback button. The client opens it and sees your list —
sections, items, hints, and &quot;Open ↗&quot; links that navigate to the right page. One natural motion per
item: <strong>click the row to check it off; click the slug button to flag a problem</strong> (that opens the
normal issue flow with screenshot and annotation, linked back to the item).</p>
<h2>The output: a coverage map, not a thread</h2>
<p>Every verdict lands in <code>session.yaml</code>:</p>
<pre><code class="language-yaml">checklist:
  items:
    - id: export-button
      title: &quot;On Reports, the Export button downloads a CSV&quot;
      verdict: pass
    - id: csv-columns
      title: &quot;The CSV has all the expected columns&quot;
      verdict: fail
      issue: &quot;03&quot;        # the annotated issue that documents it
    - id: email-sent
      title: &quot;An email arrives after an export&quot;
      verdict: null      # never checked — you know what wasn&#39;t looked at
</code></pre>
<p>Three states, not two: confirmed, flagged (with the evidence attached), and <strong>never checked</strong> — the
one a chat thread always loses.</p>
<h2>Generate the checklist from the branch</h2>
<p>Don&#39;t write the list by hand: the bundled <code>sluglist-checklist</code> skill turns the branch diff into a
client-facing checklist — user-visible changes only, grouped by feature, phrased for a
non-developer. See <a href="/docs/checklist/">Checklist mode</a>.</p>
<h2>Built for non-technical reporters</h2>
<ul>
<li>Flagging a problem takes a comment and an automatic screenshot; annotation (arrow, box, text) is
right there.</li>
<li><strong>Smart links</strong> navigate the client to the page under test; wildcard matches light up &quot;You&#39;re
here&quot; on dynamic routes.</li>
<li>The checklist panel is fully usable on a phone.</li>
<li>Reporter <a href="/docs/capture/">form fields</a> can ask what only the client knows (device, severity,
which account).</li>
<li>The client can <a href="/docs/capture/">attach their own files</a> — a phone screenshot usually arrives via
paste.</li>
</ul>
<h2>Where the feedback goes</h2>
<p>Through <a href="/docs/connectors/">a connector you own</a> — an API route in front of Vercel Blob, S3/R2 or
Supabase Storage is ~50 lines. No sluglist account, no third-party inbox holding your client&#39;s
screenshots.</p>
