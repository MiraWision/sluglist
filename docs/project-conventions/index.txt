1b:T1614,<p>The bundled skills ship with sensible defaults — base branch <code>main</code>, ask before running the app,
evidence only on failures. Every real project disagrees with some of them, and the obvious move is to
edit the skill. Don&#39;t: <code>npx sluglist init</code> <strong>never overwrites a skill you have edited</strong>, so an edited
skill stops receiving upstream improvements. That is the right safety rule and the wrong place to put
project knowledge.</p>
<p>So project specifics go in one committed file that every skill reads first:</p>
<pre class="shiki shiki-themes light-plus dark-plus" style="--shiki-light:#000000;--shiki-dark:#D4D4D4;--shiki-light-bg:#FFFFFF;--shiki-dark-bg:#1E1E1E" tabindex="0"><code><span class="line"><span>.sluglist/PROJECT.md</span></span></code></pre><p><code>npx sluglist init</code> writes the template; you fill it in and commit it. It is <strong>never overwritten</strong> —
not on re-runs, not with <code>--force</code> — because it holds your answers, not ours.</p>

<h2>Credentials are referenced, never stored</h2>
<div class="callout tint-fail"><div class="callout-mark"><svg aria-hidden="true" width="22" height="22" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="1.6" stroke-linecap="round" stroke-linejoin="round"><circle cx="12" cy="12" r="8.5"/><path d="M8.5 8.5 15.5 15.5M15.5 8.5 8.5 15.5"/></svg><span class="callout-label">Caution</span></div><div class="callout-body"><p><code>PROJECT.md</code> is committed. Never write a password, token or API key into it.</p>
</div></div><p>The file is committed, so it names <strong>where</strong> the credentials live — an env var, a seed script, a
password-manager entry — and never the values:</p>
<pre class="shiki shiki-themes light-plus dark-plus" style="--shiki-light:#000000;--shiki-dark:#D4D4D4;--shiki-light-bg:#FFFFFF;--shiki-dark-bg:#1E1E1E" tabindex="0"><code><span class="line"><span>Env vars: QA_TEST_EMAIL / QA_TEST_PASSWORD (see .env.example)</span></span>
<span class="line"><span>Sign-in page: /login</span></span></code></pre><h2>Hard limits are enforced, not advisory</h2>
<p>The limits section is the one that changes agent behaviour most sharply. Listed actions are never
completed, whatever a checklist item appears to ask for — the agent goes to the last safe step,
records the item as <strong>not tested</strong> with the reason, and moves on:</p>
<pre class="shiki shiki-themes light-plus dark-plus" style="--shiki-light:#000000;--shiki-dark:#D4D4D4;--shiki-light-bg:#FFFFFF;--shiki-dark-bg:#1E1E1E" tabindex="0"><code><span class="line"><span>- Never complete a live payment. Fill the card form, stop before Pay.</span></span>
<span class="line"><span>- Never send email to a real address. Use the catch-all inbox only.</span></span>
<span class="line"><span>- Never submit to an external/partner API from QA (orders, filings, webhooks).</span></span></code></pre><p>A &quot;not tested — stopped before Pay per PROJECT.md hard limits&quot; is a correct outcome. A pass on a live
charge is not.</p>
<h2>Loop limits bound the autonomous run</h2>
<p>When the loop is asked to fix and re-test until green, this section is what says how far it may go
without checking back:</p>
<pre class="shiki shiki-themes light-plus dark-plus" style="--shiki-light:#000000;--shiki-dark:#D4D4D4;--shiki-light-bg:#FFFFFF;--shiki-dark-bg:#1E1E1E" tabindex="0"><code><span class="line"><span>max rounds: 3</span></span>
<span class="line"><span>fix without asking: no</span></span>
<span class="line"><span>commits: leave the changes uncommitted, one summary at the end</span></span></code></pre><p><code>npx sluglist status</code> still decides <em>between</em> rounds — the loop stops on <code>stalled</code> or <code>blocked</code>
whatever the ceiling says, because an item that has already survived a fix pass belongs to a human.
See <a href="/docs/agents/">Agents &amp; CLI</a>.</p>
<h2>When it is missing</h2>
<p>The skills fall back to their own defaults and say so once, then carry on — a missing file never
blocks a run. Ask for <code>npx sluglist init</code> and the answers move into the repo, where the next person
(or the next agent) inherits them.</p>
<p>See also: <a href="/docs/agents/">Agents &amp; CLI</a> for the loop the skills run, and
<a href="/docs/checklist/">Checklist mode</a> for what the base branch feeds.</p>
