3:T1f60,<p>Beyond dev and staging, sluglist can power a <strong>&quot;Report a problem&quot;</strong> button for real users on a
production MVP or beta. It stays one-way capture; the extra pieces are reporter identity, per-issue
custom fields, and PII masking so screenshots are safe to store.</p>
<h2>Presets</h2>
<p><code>preset: &quot;beta&quot;</code> masks inputs, adds screenshot consent and relabels the launcher.
<code>preset: &quot;production&quot;</code> is <code>beta</code> plus the three things a widget needs once it faces paying
customers: PII scrubbed out of the text it collects, a way for the reporter to make it go away, and
no <code>console.warn</code> capture.</p>

<p>Every option can still be set explicitly and wins over the preset — except
<code>errors.captureWarnings</code> under <code>production</code>, which is forced to <code>false</code> (warnings are the noisiest
text channel in a real app; asking for them anyway logs a warning).</p>
<p>Mark anything sensitive with <code>data-private</code> and it is always redacted in screenshots, regardless of
<code>maskInputs</code>. Values are masked only for the screenshot render; the live DOM is restored exactly.</p>
<h2>Text scrubbing</h2>
<p>With <code>scrubText</code> on, the text surfaces of every artifact — <code>element_text</code>, the issue <code>url</code>, each
message and stack in <code>## Errors</code> (including failed-request paths), and the selectors and labels in
<code>## Actions</code> — have emails replaced by <code>[email]</code>, runs of 6+ digits by <code>[digits]</code>, and
hex/base64-shaped tokens by <code>[token]</code>. Dates, version numbers, viewport strings, stack-trace line
numbers and ordinary prose are left alone. Values <em>you</em> supply (<code>context</code>, <code>custom</code>, <code>identity</code>,
checklist titles) and the reporter&#39;s own comment are never scrubbed. Issues carry <code>scrubbed: true</code>
in their frontmatter so a reader knows which artifacts went through it.</p>
<h2>Dismiss</h2>
<p>The launcher gets a ✕ — shown on hover on desktop, always visible (muted) on touch. Clicking it
hides the widget completely, shortcut included, and remembers that for <code>dismiss.days</code> (default 7;
<code>0</code> means until storage is cleared).</p>
<p>The rescue path is <code>ui.show()</code>, which clears the dismissal immediately. Wire it to a link in your
own footer so the ✕ is never a one-way door:</p>
<pre><code class="language-ts">footerLink.addEventListener(&quot;click&quot;, () =&gt; ui.show());
</code></pre>
<h2>Self-isolation</h2>
<p>Everything the widget wraps (<code>console.error</code>, <code>fetch</code>, <code>XMLHttpRequest</code>, <code>history.pushState</code>) calls
the original host function unconditionally — a bug inside sluglist cannot fail your request,
swallow your log or block your navigation. Internal failures are counted; after five in one session
the widget uninstalls itself (originals restored by reference, listeners removed, UI taken out of
the DOM), logs one warning, and the page carries on without it.</p>
<p><strong>Zero phone-home:</strong> the widget makes no network requests except to your configured connectors —
enforced by an automated test that drives a full session with every outbound channel trapped and
asserts the count is zero.</p>
<h2>Localization</h2>
<p>Real users are the ones who need the widget in their own language. Bundles ship for <strong>en</strong>
(default), <strong>ru</strong>, <strong>uk</strong>, <strong>es</strong> and <strong>de</strong> — one line:</p>
<pre><code class="language-ts">import { labels } from &quot;sluglist/labels&quot;;

mountFeedbackWidget(widget, { strings: labels.uk });
</code></pre>
<p>Override a single string by spreading: <code>{ strings: { ...labels.uk, send: &quot;Полетіли&quot; } }</code>. Anything
a bundle leaves out falls back to English. The locale is <strong>chosen by you, not sniffed from the
browser</strong>. Plurals go through the bundle&#39;s own rule, so Slavic languages get all three forms,
including the 11–14 exception (<code>slavicPluralForm</code> is exported for custom bundles).</p>
<h2>Metadata collected</h2>
<p>Automatically, no personal data: URL path, viewport and screen size, device pixel ratio, browser
and OS (parsed from the user agent), UI language(s), timezone, color scheme, reduced-motion, and up
to the last 20 <code>console.error</code> messages. Deliberately not collected: full user agent, IP, cookies,
storage, geolocation, or any DOM content beyond the screenshot pixels.</p>
<p>Reporter <code>identity</code> and <code>custom</code> fields are collected only when you explicitly configure them; by
default neither is present in the artifacts.</p>
<h2>The production checklist</h2>
<p>Before pointing the widget at real users, walk this list. These are decisions that are <strong>yours,
not the library&#39;s</strong> — sluglist deliberately has no opinion about where your data lives, how long
you keep it, or what your privacy policy says.</p>
<ol>
<li><p><strong>Turn on the production preset</strong> (everything in the table above, at once).</p>
</li>
<li><p><strong>Gate the widget on your environment</strong> — decide at build time whether it is even constructed:</p>
<pre><code class="language-ts">if (process.env.NEXT_PUBLIC_FEEDBACK === &quot;on&quot;) {
  mountFeedbackWidget(createFeedbackWidget({ /* … */ }));
}
</code></pre>
<p><code>enabled: false</code> also works at runtime, but environment gating is stronger: it keeps the code
out of the paths you never intend to run it on.</p>
</li>
<li><p><strong>Generate and store a delivery token.</strong> Your endpoint should reject any request without a
matching bearer token, and refuse to start if the server has no token configured.</p>
</li>
<li><p><strong>Own the endpoint.</strong> Never ship storage write-keys in the browser. Post to a thin route that
owns the credentials, does the write, rate-limits, and — if you enable attachments — enforces a
server-side mime whitelist and size cap (415 / 413).</p>
</li>
<li><p><strong>Decide retention.</strong> The artifacts contain screenshots of your app as a user saw it; decide how
long they live and who can read them.</p>
</li>
<li><p><strong>Add a privacy-policy paragraph.</strong> Tell users what the &quot;Report a problem&quot; button collects; the
<a href="#metadata-collected">metadata list above</a> is the honest inventory to adapt.</p>
</li>
</ol>

<a href="https://github.com/MiraWision/sluglist/blob/main/docs/production-checklist.md"><code>docs/production-checklist.md</code></a>
and <a href="https://github.com/MiraWision/sluglist/blob/main/examples/feedback-route.ts"><code>examples/feedback-route.ts</code></a>.</p>
