19:Tfd1,<p>Test your app locally, click feedback with the widget, and have it land in a <code>.sluglist/</code> folder in
your project — then let an agent (e.g. Claude Code) read it and fix the issues. Browser JS can&#39;t
write to disk, so a tiny sidecar process, <code>sluglist dev</code>, sits between the widget and the folder.</p>
<h2>The local feedback loop</h2>
<pre><code class="language-ts">import { createFeedbackWidget, mountFeedbackWidget, LocalConnector } from &quot;sluglist&quot;;

const widget = createFeedbackWidget({
  project: &quot;my-app&quot;,
  connectors: [new LocalConnector()], // POSTs to http://127.0.0.1:4477 by default
  enabled: process.env.NODE_ENV !== &quot;production&quot;,
});
mountFeedbackWidget(widget);
</code></pre>
<p>Run the sidecar next to your dev server:</p>
<pre><code class="language-bash">npx sluglist dev                        # writes to ./.sluglist, port 4477
npx sluglist dev --dir .feedback --port 5511
</code></pre>
<p>Click feedback → the full artifact set appears under <code>.sluglist/session-*/</code>. The dev server binds
to <code>127.0.0.1</code> only and has <strong>no authentication</strong> — it is local-only by design; don&#39;t expose it or
forward its port. If it isn&#39;t running, <code>LocalConnector</code> warns once and your other connectors keep
working (the UI is never blocked).</p>
<blockquote>
<p>Add <code>.sluglist/</code> to your project&#39;s <code>.gitignore</code>.</p>
</blockquote>
<h2>Let an agent fix it (Claude Code skill)</h2>
<p>The package ships a <code>sluglist-fix</code> skill that reads <code>.sluglist/</code> and fixes the reported issues.
Install it into your project once:</p>
<pre><code class="language-bash">mkdir -p .claude/skills &amp;&amp; cp -r node_modules/sluglist/skills/sluglist-fix .claude/skills/
</code></pre>
<p>Then, after clicking feedback, ask Claude Code to <em>&quot;fix feedback&quot;</em>: it reads each issue (comment,
selector, <code>element_text</code>, screenshot, <code>## Errors</code>), localizes and fixes the code, and writes a
<code>.done</code> report into the session folder.</p>
<p>Why it works well: <a href="/docs/artifacts/">each artifact</a> is written for a file-reading agent —</p>
<ul>
<li>a <strong>CSS selector</strong> plus <code>dom_path</code> and <code>element_text</code> localize the element;</li>
<li>a <strong>React component hint</strong> (<code>component: AnimalCard</code>, read from the fiber, no React dependency
needed) localizes the source file;</li>
<li><code>## Errors</code> carries recent console errors, uncaught exceptions and failed requests with relative
timestamps;</li>
<li><code>## Actions</code> carries the click/navigation trail, cross-referenced to record-mode frames.</li>
</ul>
<p>Works with any agent that can read files — the skill is a convenience, not a dependency.</p>
<h2>Generate a checklist from a branch (the other direction)</h2>
<p>The second bundled skill, <code>sluglist-checklist</code>, turns a branch diff into a client-facing acceptance
checklist (user-visible changes only, phrased for a non-developer), written to
<code>public/checklist.json</code> — which the widget loads with <code>checklist: &quot;/checklist.json&quot;</code>. Ask Claude
Code to <em>&quot;generate a checklist from this branch&quot;</em>. See <a href="/docs/checklist/">Checklist mode</a>.</p>
<h2>Programmatic capture</h2>
<p>The UI is optional. Produce and deliver an issue without any chrome:</p>
<pre><code class="language-ts">await widget.captureIssue({
  comment: &quot;Logo overlaps the nav on narrow screens&quot;,
  mode: &quot;element&quot;,
  selector: &quot;header &gt; nav .logo&quot;,
  screenshot: pngBlob,        // optional
  category: &quot;bug&quot;,            // optional: bug | design | idea | ...
  consoleErrors: [...],       // optional, appended as a &quot;## Console errors&quot; section
});
</code></pre>
<p>See also: <a href="/for/claude-code/">sluglist for Claude Code &amp; coding agents</a> — the full workflow with
terminal transcripts.</p>
