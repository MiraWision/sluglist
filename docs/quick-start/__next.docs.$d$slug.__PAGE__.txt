3:T170d,<p>sluglist is a framework-agnostic, dependency-light widget that lets people leave visual feedback
directly on a running web app: pick an element, grab an area or the full page, annotate the
screenshot, add a comment — and the widget produces a standard set of artifacts and hands them to
pluggable <strong>connectors</strong>. The core knows nothing about where feedback is stored; delivery is fully
encapsulated in the connector you provide.</p>
<h2>Install</h2>
<pre><code class="language-bash">npm install sluglist
</code></pre>
<h2>One line of config</h2>
<p>A connector, and nothing else:</p>
<pre><code class="language-ts">import { createFeedbackWidget, mountFeedbackWidget, DownloadConnector } from &quot;sluglist&quot;;

mountFeedbackWidget(createFeedbackWidget({ connectors: [new DownloadConnector()] }));
</code></pre>
<p>That is a complete, working widget: launcher, capture modes, annotation, error and action capture,
the offline outbox, a project slug derived from your hostname. Everything else — presets, privacy,
identity, form fields, attachments, checklists, localization — is optional. Add a piece when you
need it; none of them is a setup step.</p>
<h2>Without a build step</h2>
<p>Load it from a CDN (deps inlined, exposed as <code>Sluglist</code>):</p>
<pre><code class="language-html">&lt;script src=&quot;https://unpkg.com/sluglist&quot;&gt;&lt;/script&gt;
&lt;script&gt;
  const { createFeedbackWidget, mountFeedbackWidget, DownloadConnector } = Sluglist;
  mountFeedbackWidget(createFeedbackWidget({ connectors: [new DownloadConnector()] }));
&lt;/script&gt;
</code></pre>
<p>Ships as ESM and CJS; <code>html-to-image</code> is loaded lazily on the first capture, so it is not part of
your initial bundle. Undelivered issues are persisted to IndexedDB and retried on the next load, so
a failed upload or a closed tab does not lose feedback.</p>
<h2>Three ways sluglist is used</h2>
<h3>1 · Dev loop — you and an agent</h3>
<p>Click feedback on your own app, have it land in a folder, let Claude Code fix it.</p>
<pre><code class="language-ts">import { createFeedbackWidget, mountFeedbackWidget, LocalConnector } from &quot;sluglist&quot;;

mountFeedbackWidget(createFeedbackWidget({ connectors: [new LocalConnector()] }));
</code></pre>
<pre><code class="language-bash">npx sluglist dev        # sidecar that writes to ./.sluglist
</code></pre>
<p>See <a href="/docs/agents/">Agents &amp; CLI</a> for the full loop.</p>
<h3>2 · Client acceptance — someone signs off a release</h3>
<p>Put the build on staging with a <strong>checklist</strong> of what shipped. The client walks it, checks items off
and flags problems; you get a coverage map instead of a chat thread.</p>
<pre><code class="language-ts">mountFeedbackWidget(
  createFeedbackWidget({
    project: &quot;acme&quot;,
    connectors: [new HttpConnector(&quot;/api/feedback&quot;, () =&gt; token)],
    checklist: &quot;/checklist.json&quot;,   // or an inline object
  })
);
</code></pre>
<p>See <a href="/docs/checklist/">Checklist mode</a>.</p>
<h3>3 · Beta / Production — real users report problems</h3>
<p>A &quot;Report a problem&quot; button for people who are not your team: PII masked and scrubbed, a way to
make the widget go away, and delivery through an endpoint you own.</p>
<pre><code class="language-ts">mountFeedbackWidget(
  createFeedbackWidget({
    project: &quot;acme&quot;,
    preset: &quot;production&quot;,
    connectors: [new HttpConnector(&quot;/api/feedback&quot;, () =&gt; session.token)],
    identity: { userId: user.id, email: user.email },
  })
);
</code></pre>
<p>See <a href="/docs/production/">Production &amp; privacy</a>.</p>
<h2>Attach your user</h2>
<p>Three ways to know who reported something, and they are not interchangeable — the difference is
<em>where the value comes from</em>.</p>
<table>
<thead>
<tr>
<th></th>
<th>Source</th>
<th>When it is captured</th>
<th>Lands in</th>
</tr>
</thead>
<tbody><tr>
<td><code>identity</code></td>
<td>your app already knows it</td>
<td>fixed at init</td>
<td><code>reporter</code> in session.yaml + every issue</td>
</tr>
<tr>
<td><code>setContext</code></td>
<td>live host state (tenant, flags, build)</td>
<td>at capture time</td>
<td><code>context</code> per issue</td>
</tr>
<tr>
<td><code>form</code></td>
<td>only the reporter can answer it</td>
<td>typed by them</td>
<td><code>form</code> in session.yaml or per issue</td>
</tr>
</tbody></table>
<pre><code class="language-ts">const widget = createFeedbackWidget({
  project: &quot;acme&quot;,
  connectors: [/* … */],

  // 1. What you know: static, set once.
  identity: { userId: user.id, email: user.email, name: user.name },

  // 3. What only they know: asked in the panel.
  form: [
    { id: &quot;email&quot;, label: &quot;Your email&quot;, type: &quot;email&quot;, scope: &quot;session&quot; },
    { id: &quot;severity&quot;, label: &quot;How bad is it?&quot;, type: &quot;select&quot;,
      options: [&quot;blocking&quot;, &quot;annoying&quot;, &quot;cosmetic&quot;], required: true, scope: &quot;issue&quot; },
  ],
});

// 2. What changes while they use the app.
widget.setContext({ tenantId: &quot;acme&quot;, featureFlags: &quot;new-nav&quot;, buildVersion: APP_VERSION });
</code></pre>
<p>Reach for <code>identity</code> when you have the user object, <code>setContext</code> when the answer depends on where
they are in the app, and <code>form</code> when nobody but the person reporting can tell you.</p>
