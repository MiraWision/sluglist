<p><code>session.yaml</code> carries the environment (browser, OS, viewport, screen, DPR, language(s), timezone,
color scheme, reduced-motion) plus an index of issues. Each <code>NN-{slug}.md</code> repeats the per-issue
metadata in frontmatter followed by the free-text comment.</p>
<p><strong>The structure and frontmatter are a stable contract</strong> intended as input for downstream parsers
and agents — they only ever change additively. <code>session.yaml</code> starts with
<code>format_version: &quot;1.4&quot;</code>; a missing version means <code>&quot;1.0&quot;</code>. Within a major version, new fields are
only ever added, never removed or repurposed. The full field dictionary, section rules and
versioning policy live in
<a href="https://github.com/MiraWision/sluglist/blob/main/SPEC.md">SPEC.md</a> — safe to build parsers
against.</p>

<h2>Sections an issue can carry</h2>
<ul>
<li><code>## Errors</code> — recent console errors, uncaught exceptions, promise rejections and failed network
calls, each with a relative timestamp. See <a href="/docs/capture/">error capture</a>.</li>
<li><code>## Actions</code> — the action trail: clicks, SPA navigations, submits, typing (character count only,
never content). Record-mode lines are tagged <code>— clip N, frame NN</code>.</li>
<li><code>## Console errors</code> — programmatic captures can append their own list.</li>
</ul>
<h2>Optional frontmatter blocks</h2>
<ul>
<li><code>reporter</code> — from <code>identity</code> config (never collected by default).</li>
<li><code>custom</code> — flat project fields fixed at init.</li>
<li><code>context</code> — live host state from <code>setContext</code>, merged at capture time.</li>
<li><code>form</code> — the reporter&#39;s own answers (<a href="/docs/capture/">form fields</a>).</li>
<li><code>attachments</code> — files the reporter attached, with <code>original_name</code> kept as data, never as a path.</li>
<li><code>screenshot_failed: true</code> + <code>screenshot_error</code> — when a render failed and the issue was delivered
comment-only.</li>
<li><code>scrubbed: true</code> — the artifact went through the <a href="/docs/production/">PII text scrub</a>.</li>
</ul>
<h2>Checklist verdicts</h2>
<p>When <a href="/docs/checklist/">checklist mode</a> is active, <code>session.yaml</code> additionally carries a
<code>checklist:</code> block — the coverage map of pass/fail/unchecked verdicts, each linking to the issue
that documents a failure.</p>
<h2>Selector quality</h2>
<p>Selectors prefer <code>data-testid</code> → <code>id</code> → <code>aria</code> → landmark path, and never emit Tailwind utility or
hashed CSS-Modules classes. <code>selector_strategy</code> names which rung was used and <code>selector_unique</code>
says whether it matches exactly one element — an agent can trust the selector or fall back to
<code>dom_path</code> + <code>element_text</code>.</p>
