<p>Built in: <code>MemoryConnector</code> (accumulates in memory, for tests), <code>DownloadConnector</code> (zips a whole
session via JSZip) and <code>LocalConnector</code> (POSTs to the <a href="/docs/agents/"><code>sluglist dev</code> sidecar</a>).
Real targets (blob storage, an API route, a tracker) are your own connector. <code>connectors</code> is an
array, so one issue can fan out to several destinations at once; a failing connector never blocks
the others or the UI, and delivery retries with backoff.</p>
<h2>The recommended shape: a thin API route</h2>
<p>Because the browser should never hold storage credentials, the recommended shape is a <strong>thin API
route</strong> on your side that takes the artifact and writes it server-side. The connector just posts to
it.</p>
<p><strong>Client connector (generic API route):</strong></p>
<pre><code class="language-ts">class ApiRouteConnector implements FeedbackConnector {
  id = &quot;api-route&quot;;
  constructor(private endpoint: string, private token: string) {}
  async put(sessionId: string, file: ArtifactFile) {
    const base64 = btoa(
      String.fromCharCode(...new Uint8Array(await file.blob.arrayBuffer()))
    );
    const res = await fetch(this.endpoint, {
      method: &quot;POST&quot;,
      headers: { &quot;content-type&quot;: &quot;application/json&quot;, &quot;x-feedback-token&quot;: this.token },
      body: JSON.stringify({ sessionId, path: file.path, mime: file.mime, base64 }),
    });
    if (!res.ok) throw new Error(`upload failed: ${res.status}`);
  }
}
</code></pre>
<h2>Server route — Vercel Blob</h2>
<p><code>POST /api/feedback</code>:</p>
<pre><code class="language-ts">import { put } from &quot;@vercel/blob&quot;;

export async function POST(req: Request) {
  if (req.headers.get(&quot;x-feedback-token&quot;) !== process.env.FEEDBACK_TOKEN)
    return new Response(&quot;Unauthorized&quot;, { status: 401 });
  const { sessionId, path, mime, base64 } = await req.json();
  const bytes = Buffer.from(base64, &quot;base64&quot;);
  const { url } = await put(`feedback/${sessionId}/${path}`, bytes, {
    access: &quot;public&quot;,
    contentType: mime,
    addRandomSuffix: false,
  });
  return Response.json({ ok: true, url });
}
</code></pre>
<h2>Server route — S3 / R2</h2>
<p>Same client connector:</p>
<pre><code class="language-ts">import { PutObjectCommand, S3Client } from &quot;@aws-sdk/client-s3&quot;;
const s3 = new S3Client({ region: process.env.AWS_REGION });

export async function POST(req: Request) {
  const { sessionId, path, mime, base64 } = await req.json();
  await s3.send(new PutObjectCommand({
    Bucket: process.env.FEEDBACK_BUCKET,
    Key: `feedback/${sessionId}/${path}`,
    Body: Buffer.from(base64, &quot;base64&quot;),
    ContentType: mime,
  }));
  return Response.json({ ok: true });
}

<h2>Supabase Storage</h2>
<p>Client-direct, with an insert-only RLS policy on the bucket:</p>
<pre><code class="language-ts">import { createClient } from &quot;@supabase/supabase-js&quot;;

class SupabaseConnector implements FeedbackConnector {
  id = &quot;supabase&quot;;
  private sb = createClient(URL, ANON_KEY);
  async put(sessionId: string, file: ArtifactFile) {
    const { error } = await this.sb.storage
      .from(&quot;feedback&quot;)
      .upload(`${sessionId}/${file.path}`, file.blob, {
        contentType: file.mime,
        upsert: true, // session.yaml is re-written each issue
      });
    if (error) throw error;
  }
}
</code></pre>
<h2>Piping into a tracker</h2>
<p>The artifacts are <a href="/docs/artifacts/">a stable, documented format</a> — one markdown file per issue
with YAML frontmatter. A connector (or a small job behind your endpoint) can turn each issue into a
GitHub issue, a Linear ticket, or a Slack message: parse the frontmatter, attach the screenshot,
link the session folder. Delivery stays a detail of <em>your</em> connector; the widget never learns where
feedback ends up.</p>
<h2>Delivery guarantees</h2>
<ul>
<li><strong>Fan-out:</strong> every configured connector receives every file; one failing connector never blocks
the others.</li>
<li><strong>Retries:</strong> failed deliveries retry with backoff, off the UI thread.</li>
<li><strong>Offline outbox:</strong> undelivered issues are persisted to IndexedDB and retried on the next page
load — a closed tab does not lose feedback. Disable with <code>offlineQueue: false</code>.</li>
<li><strong>No phone-home:</strong> the widget makes no network requests except to your configured connectors —
enforced by an automated test that drives a full session with every outbound channel trapped.</li>
</ul>
