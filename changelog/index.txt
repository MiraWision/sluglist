1a:Td6b8,<h1>Changelog</h1>
<h2>1.16.0 — <code>ui.open()</code></h2>
<p>One additive API. No artifact-format change (still 1.7), no behaviour change to anything that
exists, <strong>no new dependencies</strong>.</p>
<h3><code>ui.open()</code> — start the reporting flow from your own UI</h3>
<p><code>mountFeedbackWidget()</code> returned <code>dismiss()</code>, <code>isDismissed()</code>, <code>show()</code> and <code>unmount()</code>. Nothing in
that set opens the capture flow: <code>show()</code> only clears a dismissal and brings the launcher back, which
means a product that wants its <strong>own</strong> entry point — a &quot;Report a problem&quot; item in a menu, a help
panel, an empty state — could do no better than reveal the launcher and ask the reporter to go find
it in the corner. A menu item that answers a click with an instruction is a broken menu item.</p>
<pre class="shiki shiki-themes light-plus dark-plus" style="--shiki-light:#000000;--shiki-dark:#D4D4D4;--shiki-light-bg:#FFFFFF;--shiki-dark-bg:#1E1E1E" tabindex="0"><code><span class="line"><span style="--shiki-light:#0000FF;--shiki-dark:#569CD6">const</span><span style="--shiki-light:#0070C1;--shiki-dark:#4FC1FF"> ui</span><span style="--shiki-light:#000000;--shiki-dark:#D4D4D4"> = </span><span style="--shiki-light:#795E26;--shiki-dark:#DCDCAA">mountFeedbackWidget</span><span style="--shiki-light:#000000;--shiki-dark:#D4D4D4">(</span><span style="--shiki-light:#001080;--shiki-dark:#9CDCFE">widget</span><span style="--shiki-light:#000000;--shiki-dark:#D4D4D4">);</span></span>
<span class="line"><span style="--shiki-light:#001080;--shiki-dark:#9CDCFE">menuItem</span><span style="--shiki-light:#000000;--shiki-dark:#D4D4D4">.</span><span style="--shiki-light:#795E26;--shiki-dark:#DCDCAA">addEventListener</span><span style="--shiki-light:#000000;--shiki-dark:#D4D4D4">(</span><span style="--shiki-light:#A31515;--shiki-dark:#CE9178">"click"</span><span style="--shiki-light:#000000;--shiki-dark:#D4D4D4">, () </span><span style="--shiki-light:#0000FF;--shiki-dark:#569CD6">=></span><span style="--shiki-light:#001080;--shiki-dark:#9CDCFE"> ui</span><span style="--shiki-light:#000000;--shiki-dark:#D4D4D4">.</span><span style="--shiki-light:#795E26;--shiki-dark:#DCDCAA">open</span><span style="--shiki-light:#000000;--shiki-dark:#D4D4D4">());</span></span></code></pre><p><code>open()</code> opens the capture menu exactly as clicking the launcher does, and un-dismisses first when it
has to — so a call always ends with an open menu rather than an invisible one. It runs through the
same UI guard as every other entry point, so an internal failure surfaces as the widget uninstalling
itself, never as an exception inside your click handler. On a disabled widget (<code>enabled: false</code>) it is
a no-op, like the rest of the returned API.</p>
<h2>1.15.0 — <code>sluglist init</code>, project conventions, the loop skill, <code>sluglist status</code>, regression lifecycle</h2>
<p>Everything here is additive. The widget&#39;s UI, the <code>FeedbackConnector</code> contract and every existing
command and skill behave exactly as before; the one library change is a new optional field in
<code>session.yaml</code> (<strong>format 1.7</strong>, below), emitted only on a re-test run. <strong>No new dependencies.</strong> This
release upstreams the glue that had to be written by hand in every project that adopted the 1.12–1.14
agent loop, and closes the loop it left open: fix → re-test → <em>decide whether to go again</em>.</p>
<h3><code>npx sluglist init</code> — one-command project scaffold</h3>
<p><code>init-skills</code> installed the skills; four more things were identical in every integration and are now
done for you, idempotently:</p>
<ul>
<li><strong><code>.sluglist/checklists/</code></strong> — the committed-checklists convention from 1.13, as a real folder.</li>
<li><strong><code>.gitignore</code> rules</strong> — <code>.sluglist/*</code>, with <code>!.sluglist/checklists/</code> and
<code>!.sluglist/PROJECT.md</code> re-included: QA sessions stay local while the checklists (the spec) and the
project&#39;s conventions are versioned. An existing <code>.gitignore</code> is appended to, never rewritten, and
the block is not duplicated on a re-run — even if you kept the rules and dropped the comment.</li>
<li><strong>The skills</strong> — the <code>init-skills</code> step, with identical semantics and identical output.</li>
<li><strong><code>.sluglist/PROJECT.md</code></strong> — the project-conventions template (below), written only when absent.</li>
<li><strong>Agent instructions</strong>, behind <code>--agents-md</code>: a short &quot;QA loop (sluglist)&quot; section appended to
<code>CLAUDE.md</code> and <code>AGENTS.md</code> when those files exist. The CLI never prompts, so this is a flag; a
second run appends nothing.</li>
</ul>
<p><code>--dir &lt;path&gt;</code> retargets the project root, <code>--force</code> passes through to the skills step, and a re-run
reports what was created versus what was already present. <strong><code>.sluglist/PROJECT.md</code> is never
overwritten — not even with <code>--force</code></strong>: it holds your answers, not our file. <code>init-skills</code> stays as
the skills-only command.</p>
<h3><code>.sluglist/PROJECT.md</code> — project conventions as data, not skill edits</h3>
<p>The bundled skills invite you to edit them, and an edited skill is never overwritten by <code>init</code> — which
means it also stops receiving upstream improvements. That tension is now resolved in the file system
instead of in the prompts: project specifics live in one committed file that every skill reads first.</p>
<p>It is a short fill-in questionnaire: <strong>base branch</strong> for <code>branch</code>-intent diffs; <strong>how to run the app</strong>
for QA (command, port, warm-up); <strong>how to sign in</strong> (credentials <em>referenced</em> — env vars, a seed
script — never written into a committed file); <strong>hard limits</strong>, the actions QA must never complete
(live payments, real emails, external submissions), pre-filled commented-out; <strong>evidence-mode
defaults</strong> per intent; and <strong>environment quirks</strong> as free text.</p>
<p>Each bundled skill gained one short &quot;Project conventions first&quot; instruction — read the file if it
exists, its answers override the skill&#39;s defaults, and if it is absent fall back and mention that
<code>npx sluglist init</code> creates it. <code>sluglist-qa</code> also gained a hard prohibition: an action listed under
the file&#39;s hard limits is never completed, whatever a checklist item appears to ask for — the run
stops at the last safe step and records <strong>not tested</strong> with the reason.</p>
<h3><code>sluglist-loop</code> — the bundled orchestrator skill</h3>
<p>There were three per-stage skills and nothing that owned the cycle. The new fourth skill maps a
request to an intent (finished branch → <code>branch</code>, &quot;does everything still work&quot; → <code>regression</code>, a
written brief → <code>scenario</code>, after a fix pass → <code>re-test</code>), then runs the stages in order: checklist →
QA run → <code>npx sluglist report</code> + a short summary → on request fix → re-test → final report.</p>
<p>It encodes the cycle-level decisions the stage skills cannot see: the evidence-mode heuristic
(acceptance and hand-off runs → <code>all</code>, long <code>regression</code>/<code>smoke</code> sweeps → <code>fails</code>, an explicit request
always wins, <code>PROJECT.md</code> can change the defaults), the round budget, and the post-merge offer to
update the regression baseline. Stage rules are delegated, not copied — one sentence each on what a
sub-skill guarantees, and when the two disagree the stage skill wins.</p>
<p>It has <strong>two modes</strong>. <em>One pass</em> is the default and ends at the report. <em>Until green</em> is opt-in — the
user asks for it in words, or <code>PROJECT.md</code> says the loop may run unattended — and repeats
fix → re-test → decide until a stop condition fires: green, <code>stalled</code>, <code>blocked</code>, the round ceiling
(<strong>default 3 QA rounds</strong>), a hard limit, or an app that stops running. An autonomous loop has an
obvious cheat available to it, so the prohibitions name it: never edit, narrow or delete a checklist
item so it stops failing, and never record <code>wontfix</code> to end a round. <code>wontfix</code> and <code>needs_info</code>
written during an unattended run are proposals surfaced to the owner, not decisions taken on their
behalf.</p>
<h3><code>npx sluglist status</code> — is another round worth running?</h3>
<p>The new command answers the only question a loop has to get right, and answers it from the artifacts
rather than from an agent&#39;s memory of what it just did:</p>

<span class="line"><span>verdict: stalled — 1 item failed in 2 or more rounds — a fix pass has already been tried</span></span></code></pre><p>It reads the sessions on disk, chains them into rounds through <code>checklist.retest_of</code> (falling back to
the <code>&lt;id&gt;-retest-N</code> naming for pre-1.7 artifacts), and reports one verdict: <strong><code>green</code></strong> (nothing is
failing), <strong><code>continue</code></strong> (failures a fix pass can still act on), <strong><code>stalled</code></strong> (everything left has
already survived a fix pass), <strong><code>blocked</code></strong> (everything left is <code>wontfix</code> / <code>needs_info</code>) or
<strong><code>empty</code></strong>. Per item it gives the state (<code>actionable</code>, <code>awaiting-retest</code>, <code>blocked</code>), how many rounds
it has failed in, the linked issue and the fix agent&#39;s note.</p>
<p>Because it is derived, there is no new artifact and no state to keep in sync — deleting <code>.sluglist/</code>
loses history, not correctness. Chain-level rather than last-round-only: a re-test list carries only
the items that were fixed, so a coverage gap from round 1 and a failure the fix pass declined to take
both stay visible instead of quietly reading as green.</p>
<p><code>--json</code> gives an agent the same result as data, <code>--all</code> includes older chains, and a session folder
as the argument restricts the report to the chain containing it. It also covers the plain dev loop,
where the work items are the issues themselves: an issue with no record in <code>fixes.yaml</code> is open.</p>
<h3>Format 1.7 — <code>checklist.retest_of</code> in <code>session.yaml</code></h3>
<p>One additive field. The checklist <em>config</em> has carried <code>retest_of</code> since 1.5; it is now written into
<code>session.yaml</code> alongside <code>intent</code>, so the rounds of one fix→re-test cycle can be chained from the
session alone. <strong>Absent on a first-pass run</strong>, so sessions that are not re-tests are byte-identical
apart from the version line, and a 1.x parser is unaffected.</p>
<h3>Regression as a first-class checklist lifecycle</h3>
<p><code>smoke</code> produces a broad one-off pass. A standing regression list is the same kind of list with a
different life: it lives in the repo and is updated after every merge. <code>sluglist-checklist</code> now has a
documented <code>regression</code> intent with two modes:</p>
<ul>
<li><strong>Seeding</strong> (no file yet) — the smoke algorithm (routes + docs, critical paths first, ~30-item cap)
written to <code>.sluglist/checklists/regression.json</code> with <code>&quot;intent&quot;: &quot;regression&quot;</code>.</li>
<li><strong>Maintenance</strong> (the file exists) — the new part. Read the existing list <em>and</em> the branch diff, then
propose <strong>additions</strong> for new user-visible surface (1–2 loud checks per feature, folded into an
existing section when one fits) and <strong>removals</strong> for surface the diff deleted. Removals are
<strong>proposed, never silent</strong> — the user confirms. The ~30-item cap is enforced by naming what to cut
rather than growing the file. <strong>Item ids stay stable</strong> for unchanged items, because verdict history
in past sessions maps by id and a renamed id orphans it silently. The summary is a diff of the list
(<code>+ added</code> / <code>- removed</code> / <code>= unchanged</code>), not a new list.</li>
</ul>
<p>SPEC.md gains an <code>intent</code> vocabulary table with the lifecycle of each value; <code>regression</code> is
additive and the field stays an open vocabulary, so no reader needs updating.</p>

<p>Everything here is additive. The <code>FeedbackConnector</code> contract is unchanged and the widget — its UI

resolves to exactly the same tree as before, with no native binaries.</p>
<h3>Evidence for a verdict (format 1.6)</h3>
<ul>
<li><code>checklist.items[].evidence</code> in <code>session.yaml</code>: <code>screenshots</code> (files stored next to the session as
<code>ev-&lt;item-id&gt;-NN.png</code>) plus a one-line <code>note</code> (≤ 500 chars, scrubbed with the session&#39;s other
page-derived text). Absent unless recorded, so a bare verdict stays exactly as it was.</li>
<li>Writer API: <code>setVerdict(id, verdict, { evidence: { screenshots, note } })</code>. Screenshots may be

rather than a self-report); on <code>fail</code> it supplements the linked issue.</li>
<li>The reason it exists: a <code>fail</code> has always been evidenced by its issue, while a <code>pass</code> was a bare

</ul>
<h3>The anti-theatre rule (<code>sluglist-qa</code>)</h3>
<ul>
<li>New run parameter <code>evidence: &quot;fails&quot; | &quot;all&quot;</code> — <code>fails</code> is the previous behaviour and stays the

<li>The skill now states, and enforces by example, that <strong>a screenshot proves &quot;the screen looked like
this&quot;, not &quot;the action worked&quot;</strong>. For a check with no visible result (a download, a submission, a
background job) the note must carry the observed fact — the downloaded file&#39;s name and size, the

</ul>
<h3>Checklist intents (format 1.6)</h3>
<ul>
<li>Additive <code>intent</code> on the checklist config, carried into <code>session.yaml</code> as <code>checklist.intent</code>:
<code>branch</code> | <code>re-test</code> | <code>smoke</code> | <code>scenario</code> (open vocabulary — readers tolerate unknown values).</li>
<li><code>sluglist-checklist</code> gains two generator modes: <strong>smoke</strong> (a broad pass built from the app&#39;s routes
and docs, critical paths first, capped at 30 items) and <strong>scenario</strong> (a focused list decomposed
from a written brief, with anything outside the brief surfaced as a suggestion, never a silent
item).</li>
<li>Convention: checklists live in <code>.sluglist/checklists/&lt;name&gt;.json</code>. <code>sluglist dev</code> serves that

<code>public/</code>.</li>
</ul>
<h3><code>sluglist report</code></h3>
<ul>
<li>New command: <code>npx sluglist report [session-dir] [-o out.html]</code>. Zero-config — with no arguments it
reports the newest session in <code>.sluglist/</code> and writes <code>report.html</code> beside it.</li>
<li>Output is <strong>one self-contained HTML file</strong>: inlined CSS/JS, system fonts, <code>data:</code> URI images, no
external request of any kind. It opens from <code>file://</code> offline and forwards as a single attachment.</li>
<li>Contents: header (title, date, application, reporter, intent), summary tiles, the checklist as an
article with verdict badges / notes / evidence thumbnails, every issue in full with its fix status
from <code>fixes.yaml</code>, and a footer naming the format version. A session with no checklist renders as a
plain issue list.</li>
<li>Click a thumbnail for a full-size <code>&lt;dialog&gt;</code> lightbox (the full image <em>is</em> the thumbnail, scaled by
CSS — each image is stored once). A print stylesheet drops the lightbox, grids the thumbnails and
forces a light theme, so Print → Save as PDF gives a clean document.</li>
<li>Images are downscaled to 1200px and re-encoded before inlining; a typical session (5 items, 6
screenshots) lands around 150 KB. Over 25 MB the report is rebuilt once at 800px / q50 with a
warning.</li>
<li>The PNG decoder and baseline JPEG encoder are <strong>part of the CLI, written against <code>node:zlib</code>
alone</strong>. This was deliberate: <code>sharp</code> is a native binary and <code>optionalDependencies</code> install by

package whose whole runtime is two lazily-imported deps.</li>
</ul>
<h3>Internal</h3>
<ul>
<li>New dependency-free reader (<code>parseYaml</code>, <code>readSession</code>) for the subset the serializer emits, tested
differentially against a reference YAML implementation on every artifact in the repository.</li>
</ul>

<li><strong>Simpler model:</strong> click a row to <strong>check it off</strong> (grey + strikethrough); click the per-row <strong>slug

back). Replaces the three verdict buttons. Unchecking a flagged item confirms first and keeps the
issue link in <code>session.yaml</code> (a delivered issue is not retractable).</li>
<li><strong>Self-navigating accordion:</strong> finishing a section collapses it and opens the next incomplete one
(scrolled into view); manual open/close always works. A <strong>summary</strong> line
(<code>5 of 12 checked · 2 issues · 7 left</code>) replaces the bare counter; the circle badge counts what&#39;s
left, then shows <code>✓</code>. Panel <strong>auto-opens once per session</strong> when nothing is checked yet; the Done
button is gone (close via ✕ / click-outside / Esc / shortcut). New <code>config.checklist.description</code>.</li>
<li><strong>Smart links:</strong> <code>url</code> (static routes only) renders an &quot;Open ↗&quot; navigation chip; <code>url_match</code> (a
wildcard like <code>/assessments/*</code>) highlights the item with a &quot;You&#39;re here&quot; tag when the current path
matches — never navigates. Use <code>hint</code> + <code>url_match</code> for dynamic routes instead of guessing an id.</li>
</ul>
<h3>Recording clips</h3>
<ul>
<li>Each <strong>Record→Stop</strong> cycle is now its own <strong>clip</strong>. Two recordings on one issue stay two independent
clips end to end — in the modal (<code>Clip 1 · 5 frames</code>, first frame as cover, delete per clip) and in
the artifacts (<code>NN-slug-frames/clip-01/…</code>, <code>clip-02/…</code>; <code>## Actions</code> tagged <code>— clip N, frame NN</code>).
Fixes the bug where a second recording merged into the first&#39;s flat frame list.</li>
<li>Format <strong>1.1 → 1.2</strong> (additive): a <code>clips:</code> list in issue frontmatter (<code>{ id, frames }</code> per clip) and
the <code>&lt;frames_dir&gt;/&lt;clip-id&gt;/NN.png</code> layout it discriminates. Pre-1.2 recordings (flat
<code>&lt;frames_dir&gt;/NN.png</code>, no <code>clips:</code>) stay readable.</li>
</ul>
<h3>Polish</h3>
<ul>
<li>Floating circles hide while any panel is open — the <strong>Send</strong> button is never covered (was overlapped
on mobile), and modal focus order is freed.</li>
<li><code>&lt;Kbd&gt;</code> hints show the live, platform-formatted shortcut (<code>⇧F</code> / <code>Shift+F</code>, incl. a custom one) on
<strong>+ Add screenshot</strong> and the button tooltip.</li>
<li>Issue-count badge is now <strong>neutral</strong> (brand accent); red is reserved for delivery problems.</li>
<li>Frame <strong>pluralization</strong> (<code>1 frame</code> / <code>2 frames</code>), <strong>category placeholders</strong> (Bug / Design / Idea), and
<strong>aria-labels + roles</strong> on all icon buttons and the panel.</li>
</ul>
<h3>Skills &amp; docs</h3>
<ul>
<li><code>sluglist-checklist</code>: link rules (static → <code>url</code>, dynamic → <code>hint</code> + wildcard <code>url_match</code>, mixed →
both) with an explicit &quot;never invent a route id&quot;. <code>sluglist-fix</code>: clips read as separate sequences;
v2 vocabulary (checked-clean / checked-with-issue / not-tested).</li>
<li>SPEC.md → v1.2 (clips, config appendix, <code>skip</code> valid-on-read); README + landing demo updated to v2.</li>
</ul>
<h3>Scope (unchanged)</h3>
<p>The checklist is a session input; verdicts are its output — no lifecycle after the session. <code>skip</code>
stays valid on read but the v2 UI never generates it. <code>FeedbackConnector</code> is unchanged.</p>
<h2>1.8.0 — Checklist mode (structured acceptance)</h2>
<h3>Acceptance checklist + verdicts</h3>
<ul>
<li><strong><code>config.checklist</code></strong> — pass an inline <code>Checklist</code> (sections of items) or a URL string (fetched
<code>GET</code> → JSON at init). A <strong>second circle</strong> appears above the feedback button with a progress badge;
the client walks the list and records <strong>pass / fail / skip</strong> per item. Entirely opt-in — with no
checklist the widget is byte-identical to before (the elements aren&#39;t even attached).</li>
<li><strong>Fail opens the normal issue flow</strong>, linked both ways: the item stores the issue id, and the issue&#39;s
frontmatter carries <code>checklist_item</code>. A fail always has evidence — cancelling the capture leaves the
item unset.</li>
<li>Verdicts are written <strong>put-per-verdict</strong>: every click upserts <code>session.yaml</code> (same idempotent path as
per-issue writes), so progress survives the tab closing. Result: a <strong>coverage map</strong> — confirmed,
failed (with issue links), and never-checked.</li>
<li>Format <strong>1.0 → 1.1</strong> (additive): a <code>checklist:</code> block in <code>session.yaml</code> and the <code>checklist_item</code>
issue field. Missing <code>format_version</code> still means <code>1.0</code>; parsers ignore unknown fields.</li>
<li><strong><code>sluglist-checklist</code> skill</strong> (new): Claude Code turns a branch diff into a client-facing checklist
(<code>git diff &lt;base&gt;...HEAD</code>, user-visible changes only, grouped by feature, client voice) →
<code>public/checklist.json</code>. The <code>sluglist-fix</code> skill now reads the coverage map: fails are tasks,
unchecked items are reported as gaps.</li>
</ul>
<h3>Scope (deliberate)</h3>
<p>The checklist is a session input; verdicts are its output. No lifecycle after the session — no
reopening, no cross-session sync, no server-side status, and issues are never blocked on completion.
Every session runs the checklist fresh. <code>FeedbackConnector</code> is unchanged.</p>
<h2>1.7.0 — Format versioning + agent context</h2>
<h3>Artifact format is now versioned + specified</h3>
<ul>
<li><code>session.yaml</code> starts with <code>format_version: &quot;1.0&quot;</code> (always the first line). Parsers treat a missing
field as <code>&quot;1.0&quot;</code>. Within a major version the format only ever changes additively.</li>
<li>New <strong><a href="SPEC.md">SPEC.md</a></strong>: the full field dictionary (session.yaml + issue frontmatter), the
<code>## Errors</code> / <code>## Actions</code> rules, and the versioning policy — every field verified against the
generator. Safe to build parsers against.</li>
</ul>
<h3>Agent context (three additive frontmatter signals)</h3>
<ul>
<li><strong><code>component</code></strong> — in element mode, a best-effort read of the nearest named React component from the
element&#39;s fiber (no React dependency, fully guarded; <code>null</code> when absent/anonymous/minified). A direct
pointer from a report to the source file.</li>
<li><strong>Network failures in <code>## Errors</code></strong> — <code>fetch</code>/<code>XHR</code> wrappers record <em>only</em> requests that finish with
status ≥ 400 or a network error: <code>network: POST /api/animals → 500 (240ms)</code>. Never bodies, headers or
query strings. New <code>errors.captureNetwork</code> option (default true).</li>
<li><strong><code>sluglist.setContext({...})</code></strong> — attach runtime host state (tenant, feature flags, build version)
to every subsequent issue as a <code>context</code> block. Same validation as <code>custom</code>; merges on repeat calls.
Unlike <code>config.custom</code> (static at init), it reflects state at capture time.</li>
</ul>
<h3>Domain</h3>
<ul>
<li>Canonical site is now <strong>sluglist.dev</strong> (GitHub Pages via a <code>CNAME</code>); canonical/OG URLs, sitemap and
package <code>homepage</code> updated. No breaking format or connector changes.</li>
</ul>
<h2>1.6.0 — Record mode: manual frames + recording attaches to the open draft</h2>
<h3>Manual frames while recording</h3>
<ul>
<li>The recording bar gained a <strong><code>+ Frame</code></strong> button (and the <strong>S</strong> key outside text fields) to snap an
extra frame at any moment — for states auto-capture misses (hover popovers, transient toasts).
Manual snaps bypass the throttle but still respect <code>maxFrames</code>; <code>Recorder.snap()</code> is exposed.</li>
<li>The recording bar now explains itself: &quot;Frames auto-capture on clicks &amp; navigation&quot; under the
frame counter, so it&#39;s clear what record mode is doing.</li>
</ul>
<h3>Recording no longer replaces an open draft</h3>
<ul>
<li><strong>Stop &amp; describe</strong> with a draft open (e.g. record mode started from <code>+ Add screenshot</code>) now
appends the frames to that draft instead of discarding it — screenshots added before the recording
are kept, and one issue ships both (<code>screenshots</code> + <code>frames_dir</code>, no format change).</li>
<li>In the panel, a recording renders as a single stacked &quot;deck&quot; tile (tilted cards behind the first
frame, red-dot <code>N frames</code> badge) next to the regular screenshots. Click expands the numbered frame
ribbon; <code>×</code> drops the recording from the draft. Screenshots stay annotatable/removable, and
<code>+ Add screenshot</code> remains available after a recording.</li>
<li>Cancelling a recording that was started from an open draft returns to the draft unchanged.</li>
</ul>
<h3>Other</h3>
<ul>
<li>Menu reordered by expected frequency of use: Full page → Select area → Select element →
Record steps → Comment without screenshot. The <code>1</code>–<code>5</code> hotkeys now follow the position
automatically (no gaps when record mode is disabled).</li>
<li>Screenshot consent now covers recording frames too: unchecking &quot;Attach screenshot&quot; sends the
issue without frames as well (they are screenshots).</li>
</ul>
<p>No breaking changes; no artifact format changes.</p>
<h2>1.5.0 — Action trail + record mode</h2>
<h3>Action trail (new)</h3>
<ul>
<li><code>config.actions</code> — a background ring buffer of the user&#39;s recent actions (clicks, SPA navigations,
submits, typing), attached to each issue as a <code>## Actions</code> section (relative time) plus an additive
<code>actions_count</code> frontmatter field. The twin of the error capture.</li>
<li><strong>Hard PII rule (all modes):</strong> the trail records the fact and place of an action, never entered
content. <code>type</code> logs only a character count; password fields are not logged at all by default.
Navigation paths drop the query string.</li>
</ul>
<h3>Record mode (new)</h3>
<ul>
<li>A <code>Record steps</code> menu item captures a frame (masked full-page screenshot) at the start and on each
click / navigate / submit (not typing), throttled and capped. Frames link to the trail: <code>## Actions</code>
lines gain a <code>— frame NN</code> suffix, turning an issue into automatic steps-to-reproduce with images.</li>
<li>Additive format: <code>NN-slug-frames/NN.png</code> + <code>recording</code>/<code>frames_count</code>/<code>frames_dir</code> frontmatter +
<code>frames: N</code> in the session index. <code>config.recording {enabled, maxFrames, frameMinInterval}</code>.</li>
<li>The <code>sluglist dev</code> sidecar / <code>LocalConnector</code> accept a single <code>frames/</code> subfolder (still
traversal-safe). The <code>sluglist-fix</code> skill now reads Actions as steps-to-reproduce and lines frames up
with them.</li>
</ul>
<h3>Other</h3>
<ul>
<li>Default shortcut changed to <strong><code>Shift+F</code></strong> (was <code>Shift+Alt+F</code>). The focus guard still ignores it
while typing in an input/textarea/contenteditable; override via <code>config.shortcut</code>.</li>
<li>Updated the brand logo (favicon + docs). The widget button keeps its existing mark.</li>
</ul>

<h2>1.3.0 — Beta feedback mode</h2>
<p><strong>Beta feedback mode</strong> for real users on a production beta (still one-way capture: no inbox,
statuses or replies). All additive and backward compatible:</p>
<ul>
<li><strong>Identity</strong> — <code>config.identity: { userId, email, name }</code> → session-level <code>reporter</code> in <code>session.yaml</code>
and each issue&#39;s frontmatter.</li>
<li><strong>Custom fields</strong> — <code>config.custom</code> (flat primitives) → <code>custom</code> block per issue. Validated at init:
snake_case keys, non-primitives dropped with a warning, max 20 keys, values clipped to 200 chars.</li>
<li><strong>PII masking</strong> — <code>config.privacy.maskInputs</code> / <code>maskSelectors</code>; <code>[data-private]</code> is always masked.
Values are redacted to solid blocks before the screenshot render and the live DOM is restored exactly
(layout preserved). Additive <code>masked: true|false</code> in frontmatter.</li>
<li><strong>Screenshot consent</strong> — <code>config.privacy.screenshotConsent</code> adds an &quot;Attach screenshot&quot; checkbox
(default checked); unchecking sends the issue with <code>screenshot: null</code>.</li>
<li><strong>Preset</strong> — <code>config.preset: &quot;dev&quot; | &quot;beta&quot;</code>. <code>beta</code> defaults <code>maskInputs</code> + <code>screenshotConsent</code> on
and relabels the button &quot;Report a problem&quot;; any explicit option overrides the preset.</li>
<li><strong>Examples</strong> — <code>examples/HttpConnector.ts</code> + <code>examples/feedback-route.ts</code> (thin rate-limited endpoint)
showing safe production delivery without exposing storage keys in the browser.</li>

<ul>
<li>Placing text on a screenshot no longer commits and closes the annotation

synthesized click resolved to the backdrop and tripped the click-to-close
handler. Backdrop-close now requires the press to <em>start</em> on the backdrop
(standard click-outside guard), matching arrow/box behavior.</li>
</ul>

<h2>1.0.0 — Initial public release</h2>
<p>First published version. A framework-agnostic, embeddable visual feedback widget
for dev and staging sites.</p>
<h3>Capture</h3>
<ul>
<li>Four modes: <strong>element</strong> (hover-highlight + click), <strong>area</strong> (drag a rectangle),
<strong>full page</strong> (whole scrollable document), and <strong>comment only</strong>.</li>
<li>Screenshots via <code>html-to-image</code>, loaded lazily on the first capture.</li>
<li>Element capture crops the element out of a full-document render, preserving its
real background (gradients, images, surrounding context).</li>
</ul>
<h3>Annotation</h3>
<ul>
<li>Arrow, box and text tools with a color picker and undo.</li>
<li>Keyboard shortcuts (A / B / T, Ctrl/Cmd+Z, Esc, click backdrop to close).</li>
<li>Annotations are flattened onto the screenshot at full resolution.</li>
</ul>
<h3>Selectors &amp; metadata</h3>
<ul>
<li>Smart descriptive selectors: <code>data-testid</code>/<code>test</code>/<code>cy</code> → clean <code>id</code> →
<code>aria-label</code>/<code>role</code> → landmark-anchored tag path. Never emits Tailwind utility
or hashed (CSS Modules / styled-components) classes; skips auto-generated ids.</li>
<li>Per-issue metadata: <code>selector_strategy</code>, <code>selector_unique</code>, <code>element_text</code>,
<code>dom_path</code>, <code>screen</code>, plus session-level browser / OS / viewport / screen /
DPR / language(s) / timezone / color-scheme / reduced-motion and buffered
<code>console.error</code>s.</li>
</ul>
<h3>Delivery</h3>
<ul>
<li>Pluggable <strong>connectors</strong> (<code>FeedbackConnector.put</code>); the core never knows about
storage. Built-in <code>MemoryConnector</code> and <code>DownloadConnector</code> (zip). Fan-out to
several at once; failures retry with backoff and never block the UI.</li>
<li><strong>Offline outbox</strong>: undelivered artifacts are persisted to IndexedDB and
retried on the next load.</li>
<li>Stable, additive-only artifact contract: <code>session.yaml</code> index + one
<code>NN-slug.md</code> (YAML frontmatter + comment) + screenshots per session.</li>
</ul>
<h3>Integration</h3>
<ul>
<li>Configurable button (position, accent), hotkey, categories, <code>onIssueCaptured</code>
callback, mount <code>container</code>, and full string overrides (i18n).</li>
<li>Style-isolated via shadow DOM; mountable anywhere (including a Chrome
extension content script).</li>
<li>Ships as ESM and CJS with TypeScript types.</li>
</ul>
